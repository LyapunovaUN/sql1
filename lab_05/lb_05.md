## Задание 1

Выполнить анализ плана выполнения запроса с использованием `EXPLAIN ANALYZE`.

**Условие:**
Найти клиентов с фамилией `Smith`.

**Описание решения:**

Для анализа производительности запроса используется команда `EXPLAIN ANALYZE`, которая показывает фактический план выполнения и время выполнения запроса.

На основном сервере выполняется запрос без индекса:

```sql
EXPLAIN ANALYZE
SELECT * 
FROM customers 
WHERE last_name = 'Smith';
```

В результате планировщик использует **Sequential Scan (Seq Scan)** — полный перебор таблицы, так как индекс отсутствует.

Это приводит к увеличенному времени выполнения запроса.

## Задание 2

Оптимизировать запрос с помощью индекса (B-Tree).

**Описание решения:**

В локальной среде создаётся индекс типа B-Tree по полю `last_name`:

```sql
CREATE INDEX idx_customers_last_name 
ON customers(last_name);
```

После создания индекса повторно выполняется анализ:

```sql
EXPLAIN ANALYZE
SELECT * 
FROM customers 
WHERE last_name = 'Smith';
```

План выполнения изменяется:

* вместо `Seq Scan` используется **Bitmap Index Scan**;
* значительно уменьшается время выполнения запроса.

После завершения работы индекс удаляется:

```sql
DROP INDEX idx_customers_last_name;
```

## Задание 3

Оптимизировать запрос поиска закрытых дилеров.

**Условие:**
Найти дилерские центры, у которых поле `date_closed` не равно `NULL`.

**Описание решения:**

Сначала выполняется анализ без индекса:

```sql
EXPLAIN ANALYZE
SELECT *
FROM dealerships
WHERE date_closed IS NOT NULL;
```

План выполнения показывает использование **Seq Scan**, так как происходит полный перебор таблицы.


<img width="1308" height="497" alt="image" src="https://github.com/user-attachments/assets/be3177d4-b747-4380-b295-bf5c7913c44a" />


Для оптимизации создаётся **частичный индекс**, который включает только закрытые дилерские центры:

```sql
CREATE INDEX idx_dealerships_closed
ON dealerships(date_closed)
WHERE date_closed IS NOT NULL;
```

Повторный анализ:

```sql
EXPLAIN ANALYZE
SELECT *
FROM dealerships
WHERE date_closed IS NOT NULL;
```

После создания индекса:

* используется **Index Scan**;
* уменьшается время выполнения запроса;
* повышается эффективность выборки.

Удаление индекса:

```sql
DROP INDEX idx_dealerships_closed;
```

# Вывод

В ходе выполнения лабораторной работы были изучены методы анализа и оптимизации SQL-запросов:

* команда `EXPLAIN ANALYZE` для оценки плана выполнения и времени;
* различие между **Sequential Scan** и **Index Scan**;
* использование индексов типа **B-Tree** для ускорения поиска по равенству;
* применение **частичных индексов** для повышения эффективности запросов с условиями.

В результате было показано, что использование индексов значительно сокращает время выполнения запросов и снижает нагрузку на базу данных.
